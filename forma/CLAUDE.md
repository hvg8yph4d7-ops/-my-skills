# ФОРМА — личный трекер зала, еды и добавок

Это ТЗ для Claude Code. Проект вырос из переписки в чате Claude (14 сентября — 9 октября 2026):
пользователь каждый день присылал, что ел (часто фото этикеток), какие упражнения сделал,
вес, добавки, а Claude считал КБЖУ, вёл дневник и обновлял HTML-трекер.
Теперь из этого нужно сделать настоящее приложение, которое будет развиваться дальше.

В папке:
- `data/forma-data.json` — **все реальные данные** за 26 дней. Их нужно импортировать в приложение при первом запуске, ничего не потерять.
- `reference/forma-tracker-current.html` — текущий трекер (один HTML-файл). Это образец по дизайну, вкладкам и логике расчётов. Открой его в браузере, прежде чем начинать.

## 2. Что умеет текущий трекер (повторить всё)

Тёмная тема: тёмно-синий фон `#0d1b2a`, карточки `#16293f`, зелёный `#35a67c`, жёлтый акцент `#f5c542`, шрифты Oswald (цифры и заголовки) + Inter (текст). Пользователь сам выбрал гамму «синий, тёмно-зелёный, жёлтый» — сохранить.

Вкладки (горизонтальный скролл сверху):

1. **Обзор**
   - Вес (последний) + изменение с начала + график веса.
   - Жим лёжа: текущий «максимум» (ручное значение `benchMax`, сейчас 80 — примерное, до реальной проверки) + последний подход.
   - Счётчики: тренировок, дней с добавками, дней в дневнике.
   - Карточка «Без алкоголя»: дни с `soberSince`, считается сама по текущей дате, правильное склонение (день/дня/дней).
   - Средние КБЖУ + клетчатка за всё время **только по закрытым дням** (`partial: true` не учитываются), с пометкой «в норме / мало / много» относительно целей.
   - Ближайшая тренировка по сплиту + строка плана недели.
   - Схема добавок (утро / день / вечер).
   - Последний «вывод дня».
2. **Жим** — текущий подход, максимум, график прогресса, список всех подходов с расчётным максимумом и бейджем «РЕКОРД».
3. **Календарь** — месяц, пн/ср/пт подсвечены. Под каждым днём: кружок добавок (жёлтый), кружок зала (зелёный), цветные буквы групп мышц (Г грудь, С спина, Н ноги, П плечи), точка «есть запись». Тап по дню открывает карточку дня целиком: отметки, вес, жим, еда, тренировка, добавки, БЖУ + клетчатка, вывод.
4. **Тренировки**
   - «Восстановление мышц»: 6 карточек (грудь, спина, ноги, плечи, бицепс, трицепс) — когда последний раз, сколько раз всего, статус.
     Правило: большим группам нужно 3 дня, рукам 2. Статусы: «ещё рано» / «почти готова» / «восстановилась» / «давно не было» (> 8 дней).
     **Ручное переопределение `sore`**: если пользователь говорит «грудь ещё болит», ставится отметка с датой, она держится 2 дня и важнее календаря.
   - Счётчики: всего тренировок, за 7 дней, упражнений.
   - История тренировок по дням: группы мышц цветными метками, список упражнений, жим с расчётным максимумом, заметка.
5. **Дневник** — все дни подряд, новые сверху; у незакрытого дня метка «не закрыт».

## 3. Модель данных (как в `forma-data.json`)

```
targets:     { p, f, c, kcal, fib }          // цели в день: белок 130, жиры 90, углеводы 390, 3100 ккал, клетчатка 28
oldBenchMax: 107.5                           // жим до перерыва
benchMax:    80                              // текущий максимум, ручное примерное значение
split:       { 0: 'спина и бицепс', 2: 'грудь и трицепс', 4: 'плечи' }   // индекс дня недели Пн=0
soberSince:  '2026-09-09'
sore:        { 'грудь': '2026-10-04' }        // ручные отметки «ещё болит»
supplements: [{ time, items }]
marks:       { 'YYYY-MM-DD': { p: bool /*добавки*/, g: bool /*зал*/ } }
weight:      [{ date, value }]
bench:       [{ date, w, r }]                 // подходы в жиме штанги
products:    [{ name, portion, p, f, c, kcal, fib, times, note }]   // справочник частых продуктов
days: [{
  date, partial?,                             // partial = день ещё не закрыт
  groups?: ['грудь','трицепс'], trainNote?,
  work, food: [строки], training: [строки], supps?,
  macros: { p, f, c, kcal, fib },             // итог дня
  verdict                                     // короткий вывод дня
}]
```

Сейчас еда и упражнения хранятся **строками**. Для приложения лучше перейти к структуре:
- приём пищи → список позиций `{ name, grams, p, f, c, kcal, fib }`, итоги дня считаются суммой;
- упражнение → `{ name, group, sets: [{ weight, reps }] }`.
Старые строки при импорте сохранить как есть (как «текстовые позиции» с уже посчитанными итогами дня), не пытаться их насильно распарсить.

## 4. Правила расчётов (выработаны в переписке, соблюдать)

- **Расчётный максимум (e1RM)**: формула Эпли `w × (1 + reps / 30)`.
- **Средние** только по закрытым дням.
- **Макароны**: всегда уточнять, сухой или готовый вес. Готовые ≈ в 2,5 раза тяжелее сухих. Сухие (Макфа): Б 12, Ж 1,3, У 70,5, 342 ккал на 100 г. Готовые: Б 3,5, Ж 0,5, У 25, 130 ккал.
- **Курица/грудка готовая**: Б 30, Ж 3,5, 165 ккал на 100 г. Сырая ≈ Б 23.
- **Яйца**: категория важна (С0 крупнее). Если не съел желтки — вычитать.
- **Этикетка важнее базы**: когда пользователь присылает КБЖУ с упаковки — брать с неё (был случай, когда сторонняя база вдвое завысила жир бургера).
- Если блюдо приготовлено «на весь день» — считать **только съеденную часть** (пример: 20.09 пятую часть кастрюли съела девушка).
- Цели: 3100 ккал (подняли 1.10, т.к. вес стоял на 2730 ккал), белок ≥ 130, жиры до ~90 (20–30 % калорий), клетчатка 25–30 г.
- Вес: ориентир набора 0,25–0,5 кг в неделю.

## 5. Как пользователь вводит данные (ключевой сценарий)

Пользователь **не хочет заполнять формы**. Он пишет как в чат:
- «250 г готовой курицы и пачка макарон»
- фото этикетки + «съел»
- «Жим 70 на 5, потом 60 на 10, жим гантелей, хаммер…»
- «добавки пил», «вес 68,45»
- «грудь ещё болит»

Поэтому главная фича приложения — **поле ввода в свободной форме** (текст и фото), которое через Claude API превращается в структурированные записи (еда с КБЖУ, подходы, вес, отметки), показывает, что распознало, и даёт поправить одним касанием. Плюс короткий «вывод дня» от Claude.
Ручные кнопки тоже нужны (отметить добавки, зал, вес), но второстепенно.

## 6. Важная техническая проблема, которая была в чате

В артефакте claude.ai хранилище было отключено, поэтому все данные приходилось вшивать в HTML и пересобирать файл после каждого сообщения. В приложении нужно **настоящее постоянное хранилище**. Данные — ценность пользователя: экспорт/импорт JSON и резервная копия обязательны.

## 7. Рекомендуемый план (обсуди с пользователем перед стартом)

Пользователь только учится программировать (Python, Telegram-боты), поэтому стек — простой, а инструкции по запуску и деплою — пошаговые, без жаргона.

Предлагаемый вариант по умолчанию:
1. **Этап 1 — PWA**: Vite + React + TypeScript, адаптив под iPhone, установка на главный экран. Данные в IndexedDB (local-first), импорт `forma-data.json` при первом запуске, экспорт/импорт JSON. Перенести все 5 вкладок 1-в-1 с текущего HTML. Деплой бесплатно (Vercel/Netlify/GitHub Pages).
2. **Этап 2 — ввод через Claude API**: поле «что ел / что делал» + фото этикетки → разбор в записи → подтверждение. Ключ API хранить на сервере (serverless-функция), не в браузере.
3. **Этап 3 — синхронизация** между устройствами (например, Supabase), если понадобится.
4. **Дальше по желанию**: Telegram-бот как второй способ ввода; прогресс по всем упражнениям (не только жим); недельные итоги; напоминания про добавки и воду; цели с прогресс-барами.

Альтернатива, если пользователю ближе Python: Telegram-бот + веб-страница со статистикой. Спроси, что ему удобнее.

## 8. Стиль работы с пользователем

- Отвечать по-русски, коротко, по делу.
- Честно указывать на проблемы (например, перебор жира), но без занудства.
- Не трогать и не терять старые данные; любое изменение схемы — с миграцией.
- После каждого этапа — понятная инструкция «как открыть / как обновить».

**Советник правит дневник (10.10.2026).** `askAdvisor` возвращает `{ reply, actions }` по схеме `AdviceSchema` (`src/lib/advice.ts`; Gemini — `geminiStructured`, Claude — `claudeStructured`). Действия: добавить/удалить еду и упражнения (удалять можно только записи из приложения — в контексте они помечены «#N»), вес, отметки, закрыть/открыть день, нормы, план, «болит», заметка о себе, максимум жима, схема добавок. Ничего не меняется без кнопки «Применить» / «Применить всё»; `applyAction` проверяет действие и выдаёт понятную ошибку. Статусы (применено/пропущено) хранятся в переписке. В режиме клиента советник работает с дневником клиента, переписка отдельная (`chat:<id>`).

**Тренер видит переписку клиента с советником (10.10.2026).** Колонка `diaries.chat` (jsonb, см. конец `supabase/schema.sql`). Своя переписка сохраняется в аккаунт через 1,5 с после ответа (`pushChat`) и подтягивается на новом телефоне, если локально пусто. У тренера в режиме клиента во «Советнике» переключатель «Его переписка» (`ClientChat`, только чтение, автообновление 20 с) / «Мой чат о нём». Клиент согласен, отдельной пометки для клиента не нужно (решение владельца).

**Навигация как в мессенджерах (10.10.2026).** Верхняя панель (ФОРМА, ⚙, плашка клиента, вкладки) — `.top` в `App.tsx`, `position: sticky`, при прокрутке появляется тень. Подсказка «Пиши внизу…» вынесена из панели и скрыта в «Советнике».
